# 2026-10-16 — Tiger Style wave 1: first test suite (tests only)

Facts established during the solutions Tiger Style remediation wave 1
(tracker: ~/workspace/solutions-tiger-audit/ on Pax's VM):

- First test suite: `tests/tor.test.mjs` + `tests/config.test.mjs`,
  26 tests, Node's built-in runner, zero dependencies. The bundle
  scripts are loaded into a `vm` context with a stubbed `chrome`
  API, so the tests exercise the shipped code itself: EventEmitter
  delivery, Tor defaults, bootstrap-progress parsing
  (`Bootstrapped N%` → progress/status events), control-port
  command framing, the two-stage getIP extraction, and the proxy
  PAC/reset behavior — plus a config gate over `manifest.json`
  (MV3, every referenced worker/icon/page exists),
  `torbrowser/settings.json`, and `torrc/example.torrc`
  (directive shape, port ranges, hidden-service port format).
  Adversarial cases cover malformed bootstrap lines, empty
  responses, non-BUILT circuits, missing manifest targets,
  out-of-range ports, and garbage torrc lines.
- Gates on primo 2026-10-16: `node --test tests/tor.test.mjs
  tests/config.test.mjs` — 26/26 pass. (The directory form
  `node --test tests/` fails on primo's Node 22.23.3 install with
  a module-resolution error; the explicit-file form is the gate
  command.) No linter was run — no JS lint config exists in-repo.
- Quirks found in the vendored extension code, documented but NOT
  changed (vendored upstream + this repo's mirror posture; both
  are Matt's call):
  1. `tor.js` assigns `Tor.prototype` twice; the `Native` chain is
     dead, and `Native.prototype.exec` is unreachable — nothing
     in the bundle calls it.
  2. `Tor.prototype.command` reads `info['control-host']`, which
     `Tor` never sets (`info` carries `socks-host`), so the native
     `net` payload's `host` is currently `undefined`. A test pins
     this so a future fix is a deliberate, visible change.
- Nothing else was modified. `scripts/quickstart.sh` has no test
  or lint gate yet (no shellcheck on primo).
